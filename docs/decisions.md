# 历史决策

这里记录会影响后续实现的取舍。当前模块与开发步骤见[架构与技术设计](architecture/interview-review.md)。

| 决策 | 原因与后续影响 |
| --- | --- |
| 分类题库使用可直接阅读的项目资料，专项题按 ID 查 MySQL | 当前题量与访问量适合直接查询。专项题缓存与 RAG 已从应用路径移除，相关实验可以作为历史学习证据。 |
| Redis 保留用于 Lua 限流，故障时按当前规则放行 | 限流用于约束滥用和模型调用开销。Redis 异常时，面试业务按现有放行规则继续运行。 |
| 简历评分改为可选的改进建议 | 用户要知道可怎么改。建议引用简历原文，当前保存每份简历最近一次成功结果，旧评分接口退役。 |
| 原答绑定专项题，同一次复练用提交 ID 重试 | 原答消息 ID 标识需要补练的回答，提交 ID 标识一次作答。已有题目绑定和成功结果可在刷新后回看。 |
| 用原答绑定行的短事务和 `PROCESSING` 状态登记复练 | 同一原答的重复请求在调用模型前检查生成资格。模型调用位于事务之外。历史方案中的额外生成列已移除。 |
| 初始化 SQL 保持单文件 | 新用户可以一次建库、建表并得到内置题。已有库升级按涉及的任务单独设计。 |
| 面试改进按「总结定位 → 对照评估 → 稳定回看」交付 | 先验证最短的用户路径，再验证判断质量，最后解决跨刷新一致性。 [正式规格 #1](https://github.com/kris-builder/ai-interview/issues/1) |
| 本地知识库与 GitHub Issues 共用任务链接 | 长期产品规则、架构和历史决策随代码审阅；开发进度、阻塞与逐项验收在对应 Issue 更新。 [使用方式](README.md#使用-to-spec-和-to-tickets) |
