# 面试与复练产品规格

面向 Java 后端实习求职者。一次面试结束后，用户应能找到最值得补的一个知识点，从自己的原答进入一道合适的变式，并看清两次回答分别覆盖了什么。已确认的原始规格见 [GitHub Issue #1](https://github.com/kris-builder/ai-interview/issues/1)。

## 用户流程

1. 登录后，从本人保存的简历中选择一份，或输入临时简历正文，开始一场面试。同一账号最多同时进行一场。用户可以回来继续，也可以手动结束。
2. 面试结束后，整场总结引用已提交的回答，指出可改进的薄弱点。未作答时显示依据不足。
3. 用户从薄弱点查看对应轮次的原题和原答。存在匹配的专项题时可以复练，已有对照时直接查看。有分类资料时保留参考入口。题库参考答案可独立浏览。
4. 用户完成变式后，按关键点查看原答与复练的证据和缺漏。先用 Redis 库存题跑通。只答「加锁」时，应指出没有解释怎样让检查库存和扣减原子完成。补答时再单独看是否讲清库存不足的处理。
5. 稳定回看是第三阶段的目标。重开同一轮时，可查看同一份有效反馈、参考答案及专项题推荐。已有练习仍可回看。没有匹配题时，仍然可以保留点评。 [持久化任务 #4](https://github.com/kris-builder/ai-interview/issues/4)

## 首次产品验证

用同一段原答和同一学习目标，对照本项目与带有合理提示的普通 AI 对话。记录从收到反馈到提交有效变式的操作数和耗时，人工核对原子性与库存不足分支，再退出重开检查是否能继续。首轮结果用于判断是否值得扩展到更多知识点。真实模型效果和用户验收分别记录。

本轮范围沿用父规格。扩充大题库、移动端重做、RAG、语音面试、总分体系和主动重评留待另行讨论。任务顺序和验收入口见[知识库首页](../README.md)。
